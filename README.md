# Лендинг с видео на скролле

Страница, где фоновое видео перематывается вашей прокруткой — сайт не проигрывает видео, он *и есть* видео. Крутите вниз — дом достраивается, крутите вверх — ремонт разбирается обратно.

Сделано на примере недвижимости, но приём работает для любого продукта: товар поворачивается, механизм собирается, процесс идёт вперёд и назад под пальцем.

## Что умеет

- **Видео на скролле.** Фон перематывается кадр за кадром, вперёд и назад.
- **Заставка.** При заходе видео само играет до 4-й секунды, замирает и передаёт управление скроллу. Начали листать раньше — заставка обрывается сразу.
- **Три слоя параллакса.** Фон, страница и 22 отдельных элемента едут каждый со своей скоростью.
- **Инерционный скролл.** Считается по времени, поэтому ощущение одинаковое на 60 и 144 Гц.
- Фото во весь экран со стрелками, форма заявки, боковая шкала разделов, счётчики, плёночное зерно.
- Плеер YouTube грузится только по клику — его скрипты тяжёлые и отнимают кадры у скролл-видео.

Ни сборки, ни зависимостей, ни фреймворка. Один HTML-файл.

## Главное: как кодировать видео

Это единственное место, где проект можно сломать, и ломается он именно здесь.

Обычное видео хранит один ключевой кадр в секунду. Браузеру приходится декодировать до 30 промежуточных кадров на каждую перемотку — и скролл дёргается. Никакая настройка в коде это не лечит.

**Рабочая команда** (одной строкой, работает и в PowerShell, и в cmd):

```
ffmpeg -i source.mp4 -vf "scale=960:-2,fps=30" -c:v libx264 -preset slow -crf 24 -g 1 -keyint_min 1 -sc_threshold 0 -pix_fmt yuv420p -an -movflags +faststart video\scroll.mp4
```

| Ключ | Зачем |
|---|---|
| `-g 1` и `-keyint_min 1` | ключевой кадр на каждом кадре. **Оба должны совпадать** — если поставить разные значения, x264 пересогласует их по-своему и результат будет непредсказуем |
| `scale=960` | 720p при перемотке тяжёл сам по себе: браузер декодирует полный кадр на каждое движение колеса |
| `-crf 24` | при `-g 1` кодек сжимает каждый кадр как отдельную картинку, поэтому нужен запас качества |
| `fps=30` | должно совпадать с `FPS` в `index.html` |
| `-an` | звук не используется, только вес |
| `+faststart` | видео играет до полной загрузки |

Минута такого ролика весит около 34 МБ.

**Проверьте результат.** Должно вывести число около 300:

PowerShell:
```powershell
(ffprobe -v error -select_streams v:0 -show_entries frame=key_frame -of csv=p=0 -read_intervals "%+#300" video\scroll.mp4 | Select-String "^1$").Count
```

cmd:
```
ffprobe -v error -select_streams v:0 -show_entries frame=key_frame -of csv=p=0 -read_intervals "%+#300" video\scroll.mp4 | find /c "1"
```

Вывело 10 — ключи не сработали, лаги останутся.

**Если всё ещё дёргается** — уменьшайте разрешение: `scale=854`, затем `scale=768`. Плавность важнее резкости, видео всё равно идёт под затемнением.

**Если плавно и хочется чище** — поднимайте до `scale=1152`.

## Под свой проект

1. Закодированное видео → `video/scroll.mp4`
2. Пять фотографий → `video/`, имена те же
3. Текст правится прямо в `index.html`, это обычный HTML
4. Поменяли частоту кадров — обновите `FPS` в скрипте
5. Свой ролик с YouTube — поменяйте `VIDEO_ID` в конце скрипта и адрес обложки в разметке

### Настройки

```js
var INTRO_END = 4;    // секунд играет заставка
var FPS = 30;         // должно совпадать с вашим видео
var ease   = 0.075;   // инерция контента
var bgEase = 0.055;   // инерция фона — он отстаёт от контента
```

Меньше число — длиннее докат. **Ниже `0.05` не ставьте:** видео будет перематываться ещё несколько секунд после остановки колеса, и это читается как подтормаживание.

Глубина параллакса задаётся у каждого элемента в разметке:

```html
<figure class="card" data-par="0.18">
```

`0.04` почти незаметно, `0.18` сильно. В галерее значения разные, поэтому фото расходятся при прокрутке.

## Публикация

Статический сайт. Settings → Pages → deploy from `main` / root.

Работает и по двойному клику на `index.html`, с одной оговоркой: плеер YouTube по файловому протоколу выдаёт ошибку 153, поэтому локально видео открывается в новой вкладке. На настоящем сайте плеер встраивается в страницу.

## Как это устроено

Три независимых слоя, каждый со своей скоростью:

1. **Фон** — своя инерция, отстаёт от контента, наезжает и медленно уходит вверх
2. **Страница** — основная инерция, разгон и докат
3. **22 элемента** — каждый со своим `data-par`

Кадр видео привязан к контенту, а не к фону. Смещение фона тянется лениво, а перемотка замирает быстро — иначе видео перематывалось бы ещё девять секунд после остановки колеса и заметно подтормаживало.

Двигаются только элементы, попавшие в кадр, а их положения считаются один раз при загрузке — иначе браузер пересчитывал бы вёрстку каждый кадр.

Восстановление позиции при F5 отключено намеренно: на странице с фиксированной обёрткой восстановленная прокрутка рассинхронизирована с внутренним счётчиком, и видео начинало играть само по себе.

## Браузеры

Chrome, Edge, Safari, Firefox. На телефонах инерция отключается и работает нативный скролл — свой плавный скролл конфликтует с адресной строкой. Учитывает `prefers-reduced-motion`.
